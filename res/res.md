# ServerApp2

## Практична робота №2

**Тема:** Сокетне програмування та обмін повідомленнями по TCP/UDP.

## Опис проєкту

ServerApp2 — консольний мережевий сервіс диспетчеризації та телеметрії, реалізований мовою Go.

Сервер одночасно працює з двома мережевими протоколами:

* TCP — для надійного обміну командами та повідомленнями з клієнтами;
* UDP — для прийому телеметричних даних від зовнішніх джерел.

TCP-сервер використовує модель «горутина на кожне з'єднання». Підключені клієнти зберігаються в потокобезпечній колекції та можуть отримувати широкомовні повідомлення.

## Структура проєкту

```text
ServerApp2/
├── res/
|   └── res.md
├── Main.go
└── README.md
```

## Мережеві порти

| Протокол | Порт | Призначення                      |
| -------- | ---: | -------------------------------- |
| TCP      | 9000 | Команди та повідомлення клієнтів |
| UDP      | 9001 | Прийом телеметрії                |

## Запуск

Перейти до каталогу проєкту:

```bash
cd ServerApp2
```

Запустити сервер:

```bash
go run .
```

Або виконати запуск із перевіркою станів гонитви:

```bash
go run -race .
```

## Очікуваний запуск сервера

```text
=== Мережевий сервіс диспетчеризації (TCP: 9000, UDP: 9001) ===

[СЕРВЕР] TCP-слухач відкрито на порту 9000
[СЕРВЕР] UDP-слухач телеметрії відкрито на порту 9001
```

Після цього сервер очікує TCP-підключення та UDP-датаграми.

## Перевірка TCP

Для підключення можна використати `nc`:

```bash
nc localhost 9000
```

Після підключення сервер надсилає:

```text
[СЕРВЕР] Ласкаво просимо до мережевого сервісу диспетчеризації!
[СЕРВЕР] Доступні команди: ECHO, TIME, BROADCAST, MSG, CLOSE, QUIT
```

### Команда ECHO

Ввести:

```text
ECHO Тестове повідомлення
```

Результат:

```text
[ECHO]: Тестове повідомлення
```

### Команда TIME

Ввести:

```text
TIME
```

Приклад результату:

```text
[TIME]: 2026-09-24T08:15:30+03:00
```

Фактичний час залежить від моменту запуску.

### Команда BROADCAST

В одному TCP-клієнті:

```text
BROADCAST Усім привіт!
```

Інші підключені клієнти отримають:

```text
[СПОВІЩЕННЯ від 127.0.0.1:xxxxx]: Усім привіт!
```

Клієнт, який відправив повідомлення, не отримує власну розсилку.

Також підтримується альтернативна команда:

```text
MSG Текст повідомлення
```

### Команда CLOSE

```text
CLOSE
```

Сервер відповідає:

```text
[СЕРВЕР] З'єднання буде закрито. До побачення!
```

Після цього поточне TCP-з'єднання закривається.

### Команда QUIT

Команда:

```text
QUIT
```

працює аналогічно `CLOSE`.

### Невідома команда

Наприклад:

```text
HELLO
```

Сервер повертає:

```text
[ПОМИЛКА] Невідома команда. Доступні: ECHO, TIME, BROADCAST, MSG, CLOSE, QUIT
```

## Перевірка кількох клієнтів

Необхідно відкрити декілька терміналів.

Термінал 1:

```bash
nc localhost 9000
```

Термінал 2:

```bash
nc localhost 9000
```

Термінал 3:

```bash
nc localhost 9000
```

У консолі сервера з'являться повідомлення:

```text
[ПІДКЛЮЧЕННЯ] Новий клієнт: 127.0.0.1:54120
[ПІДКЛЮЧЕННЯ] Новий клієнт: 127.0.0.1:54135
[ПІДКЛЮЧЕННЯ] Новий клієнт: 127.0.0.1:54142
```

При виконанні:

```text
BROADCAST Повідомлення для всіх
```

двома іншими клієнтами буде отримано:

```text
[СПОВІЩЕННЯ від 127.0.0.1:54120]: Повідомлення для всіх
```

## Перевірка UDP

UDP-порт працює на `9001`.

Для тестування через `nc`:

```bash
nc -u localhost 9001
```

Після підключення можна відправити:

```text
temp=24.5;press=750
```

У серверній консолі з'явиться:

```text
[UDP ТЕЛЕМЕТРІЯ] Отримано 18 байт від 127.0.0.1:58902 -> "temp=24.5;press=750"
```

Підключені TCP-клієнти отримають:

```text
[TELEMETRY from 127.0.0.1:58902]: temp=24.5;press=750
```

Таким чином UDP використовується як джерело телеметричних подій, а TCP — як канал доставки цих подій диспетчерам.

## Graceful Shutdown

Для завершення сервера використовується сигнал `SIGINT` або `SIGTERM`.

Найпростіший варіант — натиснути:

```text
Ctrl+C
```

Після цього сервер виконує такі дії:

1. припиняє прийом нових TCP-з'єднань;
2. припиняє прийом UDP-датаграм;
3. визначає кількість активних клієнтів;
4. надсилає їм `SERVER_SHUTTING_DOWN`;
5. закриває їхні мережеві з'єднання;
6. очікує завершення обслуговуючих goroutine;
7. завершує роботу процесу.

Приклад:

```text
^C

[СЕРВЕР] Отримано сигнал завершення роботи.
[СЕРВЕР] Запуск Graceful Shutdown...
[СЕРВЕР] Сповіщено активних клієнтів: 2. З'єднання закриті.
[СЕРВЕР] Усі серверні горутини завершено.
[СЕРВЕР] Роботу сервера успішно завершено.
```

TCP-клієнт перед закриттям отримує:

```text
[СИСТЕМА]: SERVER_SHUTTING_DOWN
```

## Перевірка Race Detector

Для перевірки потокобезпечності використовується:

```bash
go run -race .
```

Після цього потрібно виконати тестування з декількома TCP-клієнтами та одночасно надсилати UDP-телеметрію.

Коректний результат не повинен містити:

```text
WARNING: DATA RACE
```

Використання `sync.RWMutex` забезпечує синхронізований доступ до колекції активних клієнтів.

Окремий `sync.Mutex` у структурі `Client` синхронізує операції запису до конкретного TCP-з'єднання.

## Виконані рівні практичної роботи

### Рівень 1

Реалізовано TCP-сервер на порту `9000`, прийом клієнтів через `Accept()` та окрему goroutine для кожного підключення.

Реалізовано текстовий протокол із завершенням повідомлень символом нового рядка.

Підтримуються команди `ECHO`, `TIME`, `CLOSE` та `QUIT`.

### Рівень 2

Додано реєстрацію активних клієнтів.

Для захисту колекції використовується `sync.RWMutex`.

Реалізована широкомовна команда `BROADCAST`, а також її скорочений варіант `MSG`.

Системні повідомлення про підключення та відключення також передаються активним клієнтам.

### Рівень 3

Додано UDP-приймач на порту `9001`.

Отримані UDP-датаграми перетворюються на телеметричні повідомлення та передаються TCP-клієнтам.

Реалізовано перехоплення `SIGINT` і `SIGTERM`.

При завершенні сервер коректно закриває TCP та UDP слухачі, повідомляє клієнтів, закриває їхні з'єднання та очікує завершення goroutine.

## Висновок

У межах практичної роботи було реалізовано мережевий сервіс диспетчеризації мовою Go. Сервер підтримує одночасну роботу з TCP-клієнтами та UDP-джерелами телеметрії.

Для TCP реалізовано модель обслуговування «горутина на кожне з'єднання», текстовий протокол команд та широкомовну передачу повідомлень. Для роботи з колекцією активних клієнтів застосовано синхронізацію через `sync.RWMutex`, а операції запису в окремі TCP-з'єднання захищаються власним mutex клієнта.

UDP-частина дозволяє приймати незалежні датаграми телеметрії та транслювати їх усім активним TCP-клієнтам.

Також реалізовано Graceful Shutdown із перехопленням сигналів операційної системи. Перед завершенням роботи сервер повідомляє клієнтів, закриває мережеві ресурси та очікує завершення обслуговуючих goroutine.

Перевірка за допомогою `go run -race .` використовується для контролю відсутності станів гонитви під час конкурентної роботи сервера.
